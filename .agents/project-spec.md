## 1. 회원·소유·로그인 (2026-11-05 사용자 결정)

- **회원**: 아이디+비밀번호 가입(이메일 없음). Supabase Auth 는 이메일이 필수라 `아이디@<고정 도메인>` 형태의 가상 이메일로 변환해 쓴다.
  세션은 `@supabase/ssr`(새 런타임 의존성, 쿠키 세션용). 아이디 규칙(2026-11-11): 4~20자, 영문 소문자 · 숫자 · `_`. 비밀번호 8자 이상. 아이디는 `app_metadata.login_id` 에도 둔다(표 없음).
  이메일이 없으니 비밀번호 찾기는 불가. 사이트 운영용 관리자 기능은 지금 만들지 않으므로(아래 "관리자") 재설정(2026-11-11): API 키가 연결된 계정은 키로 로그인해 새로 설정, 키 없는 계정은 복구 불가(가입 화면에 안내).
- **같은 Supabase 프로젝트에 냠냠캔버스가 함께 있다(2026-11-08 사용자 지시)**: `nyamnyam` 스키마 + Supabase Auth 를 쓰며 곧 비울 예정. 그 전까지는
  - 프로젝트 전체 인증 설정(Confirm email·Site URL·Redirect URLs)과 `nyamnyam` 스키마를 건드리지 않는다. → Confirm email 을 끄는 대신
    메이플 가입은 **서버에서 `auth.admin.createUser`**(이메일 확인 완료 상태로 만들기) + `app_metadata.app = "maple"`.
  - 메이플 로그인은 `app_metadata.app = "maple"` 인 계정만 받는다(냠냠 계정으로 들어오지 못하게).
  - service role 키는 서버 전용(환경변수, `NEXT_PUBLIC_` 아님).
- **로그인 방법(2026-11-08 사용자 확정: 아이디 로그인 + API 키 로그인 둘 다)**:
  1. **아이디 로그인**(아이디+비밀번호, 위). API 키 없이 내 수익만 쓰는 사람도 있으므로 반드시 둔다.
  2. **API 키 로그인**: 키를 넣으면 서버가 `/maplestory/v1/ouid` 로 넥슨 계정 고유값(ouid)을 받아 그 ouid 에 연결된 계정으로 로그인,
     없으면 새로 만든다. ouid 는 키를 다시 발급해도 그대로라 계정 기준으로 쓸 수 있다(확인 필요). 같은 키를 숙제·보스 수익·강화 기록용으로 암호화 저장.
     아이디로 가입한 사람은 내 정보에서 키를 등록하면 ouid 가 연결되어 이후 두 방법 모두로 로그인.
     구현: 서버에서 키 확인 → Supabase admin API(service role, 서버 전용)로 사용자 찾기/만들기 → 세션 발급. 인증 변경이라 Codex 리뷰 기본 모델.
     주의: 키가 유출되면 계정도 열리므로 키 교체 안내, 로그인 시도 횟수 제한.
  3. **넥슨 로그인**(게임 데이터 활용 로그인) — 공식 안내상 지정 제작자(메이플지지·메애기·츄츄지지·메이플 히스토리)에게만 제공 → 지금은 불가.
     신청 절차가 열려 있는지는 확인 필요.
- **로그인과 API 키는 별개(2026-11-07 정리)**: 로그인 = 내 메이플을 쓰려면 반드시 필요, 방법은 아이디 **또는** API 키 중 하나.
  API 키 등록 = 숙제·보스 수익 기록·강화 기록, 내 수익의 보스 수익 자동 빼기·계정 묶기에 필요(선택). **여러 개 등록 가능**(넥슨 계정 1개 = 키 1개, §4-5). API 키로 로그인하면 키가 자동으로 등록된 것으로 친다. 아이디로 로그인한 사람은 내 정보에서 키를 따로 등록.
- **소유 구조**: 우리 계정 1개에 넥슨 계정(API 키) 여러 개를 묶을 수 있다(§4-5). 새 테이블은 처음부터 `user_id NOT NULL` + RLS `auth.uid() = user_id`.
- **기존 데이터는 옮기지 않고 새로 시작(2026-11-08 사용자 결정)**. 개편 전 DB 백업은 `C:\dev\_backup\maple-db-2026-11-08\`(public 테이블 5개 JSON, git 밖).
  옛 public 테이블(`workers`·`hunting_logs`·`fragment_sales`·`settlements`·`log_entries`)과 그 트리거·함수는 새 사이트를 배포할 때 삭제(삭제 SQL 은 실행 전에 사용자에게 보여 줌).
- **로그인 범위(2026-11-08 바뀜)**: 홈·분배금 계산기·기댓값 계산기·MVP 계산기·썬데이 메이플·숨은 스펙업·핀볼 추첨·보스 도우미는 비로그인 공개.
  계정·세션은 사이트 전체에 하나(헤더에 로그인 상태).
  - **보스 수익 "이번 주 얼마 버는지"(조회) = API 키만 있으면 비회원도 가능.** 비회원 키는 브라우저(localStorage)에만 두고 브라우저가 넥슨 API 를 직접 부른다
    (maple-to-do.com/scheduler 가 이 방식: 키를 서버로 안 보냄, 초당 4건으로 나눠 호출, 30분 보관). 넥슨 API 의 브라우저 직접 호출(CORS) 허용은 우리 코드로 다시 확인.
    화면에 "키 지우기". 이 경로만 클라이언트에서 외부 API 를 부르는 예외다(우리 DB·Supabase 는 그대로 서버에서만).
  - **내 수익, 보스 수익 기록(날짜별 누적·달력·물욕 기록·가격 설정), 숙제, 강화 기록, 알림, 내 정보 = 로그인 필요.** 로그인 없이 쓰는 "기기 저장 모드" 없음.
    로그인 회원의 키는 지금 설계대로 서버에 암호화 저장.
  - MVP 계산기의 주차별 결제 금액만 비회원이면 브라우저, 로그인하면 계정에 저장(§4-9).
- **로그인 상태 4가지(시안 `A-states`, 2026-11-08)**:
  - 비회원: 내 메이플 = 로그인 화면(아이디 로그인 **또는** API 키 로그인), 홈 "이번 주" 자리 = 작은 로그인 유도 카드(+ "API 키로 보스 수익만 보기") + **내 수익 소개**(§4-5).
    홈 전체를 로그인 창으로 덮지 않음. 보스 수익 = API 키 입력 화면(이 브라우저에만 저장).
  - 비회원 + API 키(이 브라우저): 홈 "이번 주" = 이번 주 보스 수익 + 로그인 유도, 보스 수익 = 이번 주만(달력·물욕 기록 자리는 "로그인하면 쌓여요" 안내). 그 밖의 내 메이플 = 로그인 화면.
  - 아이디만: 홈 "이번 주" = 내 수익 요약 + "API 키 등록" 카드(2026-11-08 오전 결정의 "최근 정산"을 내 수익으로 바꿈).
    숙제·보스 수익·강화 기록 = "API 키 등록" 안내, 내 수익(캡처 기록)·알림은 그대로.
  - API 키 있음: 전부. 내 수익에 보스 수익 자동 빼기와 계정별 묶기가 더해진다.
- **내 정보 화면**: API 키 등록·교체·삭제. 시안에 없어 코드에서 A안 스타일로 바로 만든다(2026-11-08 사용자 결정).
- **관리자(2026-11-08 사용자 결정)**: 옛 관리자 방식(`/admin` 페이지, `ADMIN_PASSWORD`, 관리자 쿠키·Server Actions)은 **통째로 없앤다**.
  사이트 운영용 관리자 기능은 지금은 만들지 않는다(필요해지면 그때 `app_metadata.role` 등으로 설계). `ADMIN_PASSWORD` 환경변수(Vercel·`.env.local`)는 새 코드가 운영 배포된 뒤 삭제.

## 3. 넥슨 Open API (2026-11-07 공식 페이지 확인)

   - **조각 가격 · 현금화 비율 = "가격 설정"으로 따로(2026-11-08 사용자 요청)**: 화면 위쪽 메소/원 전환 옆 "가격 설정" 버튼(닫혀도 "조각 550만 · 1억당 2,900원" 요약이 보임) → 누르면 열리는 칸에
     "조각 가격 (1개, 메소)"(기본 5,500,000)·"현금화 비율 (1억당 원)"(기본 2,900). 바꾸면 다음 기록에도 들어간다.
   - **계산 결과 카드(옛 부주 정산 결과 카드처럼)**: 기록 칸 아래 왼쪽 = 계산 내역(메소 · 조각 n개 × 가격 · 수수료 3% 뺌 · 보스 수익 − → 합계), 오른쪽 = 주황 강조 카드 "오늘 사냥 수익" 원 큰 숫자 + 메소 합계 + "합계 × 1억당 n원". 고친 가격은 다음 기록에도 들어간다.
   - **"사용"(강화에 쓴 메소)·"외부 유입"(현금 충전) 메모는 두지 않는다**(2026-11-08 사용자 결정). 0에서 시작하니 필요 없다. 그래서 월간의 "쓴 것·순증감"도 없앴다.
   - **보기**: 오늘·주간·월간 사냥 수익 + 지금 들고 있는 것(메소 · 조각) 4칸, 달력(일~토, "보스 뺌"·"기록 없음" 표시), 누적 사냥 수익 그래프(10일·30일·90일·1년),
     주간 표(합계 기준은 게임 주기 목~수: 사냥 수익 · 보스 수익(따로, 참고)), 월간(사냥으로 번 것 · 보스 수익(따로) · 합계), 단위 원/메소 전환.
   - **보스 수익은 내 수익에 더하지 않는다**: 주간 표의 보스 수익 칸은 참고용(키 있을 때, 보스 수익 화면 값).
   - **여러 계정**: API 키를 여러 개 등록하면 계정별로 캐릭터를 묶어 보여 준다(계정 = 묶음 하나). 같은 계정·같은 월드는 메소를 같이 쓰니 한 번만, 조각은 캐릭터별 합산(meso.kr 방식, 확인 필요).
   - **홈 첫 화면에서 "내 수익"으로 무엇을 할 수 있는지 한눈에**(비로그인 홈): 캡처 한 장으로 기록 · 0에서 시작하면 끝 · 보스 수익은 자동으로 빼기 · 여러 계정 묶어 보기, 사용법 3단계(0으로 비우고 사냥 → 캡처 붙여넣기 → 확인·저장).
   - 시안: `Income.dc.html`(props `auth` key·id, `capture` read·empty), A 의 screen `income`.
   - **보스 수익(§4-6)은 합치지 않고 따로 둔다(2026-11-08 사용자 확인)** — 열리는 조건(비회원 + 키로도 이번 주 조회)과 설정(파티원·가격·물욕)이 달라서. 두 화면을 서로 링크로 잇는다.
   - **보관(시안만, 2026-11-08)**: 옛 "부주 정산" 화면(정산 기준 | 줄 금액 결과 카드, 복사 = 숫자만 `57000`, Web Share 공유, 부주 몫 % 칸 없음, 인센티브 = 실제로 준 금액이 계산보다 많은 차이,
