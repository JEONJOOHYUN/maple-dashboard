## 1. 회원·소유·로그인 (2026-11-05 사용자 결정)

- **회원**: 아이디+비밀번호 가입(이메일 없음). Supabase Auth 는 이메일이 필수라 `아이디@<고정 도메인>` 형태의 가상 이메일로 변환해 쓴다.
  세션은 `@supabase/ssr`(새 런타임 의존성, 쿠키 세션용). 아이디 규칙(길이·문자)은 여기서 정한다(미정).
  이메일이 없으니 비밀번호 찾기는 불가. 사이트 운영용 관리자 기능은 지금 만들지 않으므로(아래 "관리자") 재설정 방법은 3단계에서 정한다(확인 필요).
- **같은 Supabase 프로젝트에 냠냠캔버스가 함께 있다(2026-11-08 사용자 지시)**: `nyamnyam` 스키마 + Supabase Auth 를 쓰며 곧 비울 예정. 그 전까지는
  - 프로젝트 전체 인증 설정(Confirm email·Site URL·Redirect URLs)과 `nyamnyam` 스키마를 건드리지 않는다. → Confirm email 을 끄는 대신
    메이플 가입은 **서버에서 `auth.admin.createUser`**(이메일 확인 완료 상태로 만들기) + `app_metadata.app = "maple"`.
  - 메이플 로그인은 `app_metadata.app = "maple"` 인 계정만 받는다(냠냠 계정으로 들어오지 못하게).
  - service role 키는 서버 전용(환경변수, `NEXT_PUBLIC_` 아님).
- **로그인 방법(2026-11-08 사용자 확정: 아이디 로그인 + API 키 로그인 둘 다)**:
  1. **아이디 로그인**(아이디+비밀번호, 위). API 키 없이 부주 정산만 쓰는 사람도 있으므로 반드시 둔다.
  2. **API 키 로그인**: 키를 넣으면 서버가 `/maplestory/v1/ouid` 로 넥슨 계정 고유값(ouid)을 받아 그 ouid 에 연결된 계정으로 로그인,
     없으면 새로 만든다. ouid 는 키를 다시 발급해도 그대로라 계정 기준으로 쓸 수 있다(확인 필요). 같은 키를 숙제·강화 기록용으로 암호화 저장.
     아이디로 가입한 사람은 내 정보에서 키를 등록하면 ouid 가 연결되어 이후 두 방법 모두로 로그인.
     구현: 서버에서 키 확인 → Supabase admin API(service role, 서버 전용)로 사용자 찾기/만들기 → 세션 발급. 인증 변경이라 Codex 리뷰 기본 모델.
     주의: 키가 유출되면 계정도 열리므로 키 교체 안내, 로그인 시도 횟수 제한.
  3. **넥슨 로그인**(게임 데이터 활용 로그인) — 공식 안내상 지정 제작자(메이플지지·메애기·츄츄지지·메이플 히스토리)에게만 제공 → 지금은 불가.
     신청 절차가 열려 있는지는 확인 필요.
- **로그인과 API 키는 별개(2026-11-07 정리)**: 로그인 = 내 메이플을 쓰려면 반드시 필요, 방법은 아이디 **또는** API 키 중 하나.
  API 키 등록 = 숙제·강화 기록에만 필요(선택). API 키로 로그인하면 키가 자동으로 등록된 것으로 친다. 아이디로 로그인한 사람은 내 정보에서 키를 따로 등록.
- **소유 구조**: 계정 1개가 부주 여러 명을 관리(지금 탭 구조 유지). 새 테이블은 처음부터 `user_id NOT NULL` + RLS `auth.uid() = user_id`.
- **기존 데이터는 옮기지 않고 새로 시작(2026-11-08 사용자 결정)**. 개편 전 DB 백업은 `C:\dev\_backup\maple-db-2026-11-08\`(public 테이블 5개 JSON, git 밖).
  옛 public 테이블(`workers`·`hunting_logs`·`fragment_sales`·`settlements`·`log_entries`)과 그 트리거·함수는 새 사이트를 배포할 때 삭제(삭제 SQL 은 실행 전에 사용자에게 보여 줌).
- **로그인 범위**: 홈·분배금 계산기·기댓값 계산기·핀볼 추첨·보스 도우미는 비로그인 공개. 계정·세션은 사이트 전체에 하나(헤더에 로그인 상태).
  **"내 메이플"(숙제·보스 수익·강화 기록·부주 정산·알림)과 내 정보는 전부 로그인 필요**(2026-11-07 확정, 2026-11-08 다시 확인 — 로그인 없이 쓰는 "기기 저장 모드" 없음).
  비로그인: 내 메이플 탭 = 로그인 화면(아이디 로그인 **또는** API 키 로그인 중 하나를 고름), 홈의 "이번 주" 자리 = 작은 로그인 유도 카드(무엇을 볼 수 있는지 + 로그인 버튼,

  **아이디만 로그인한 상태의 홈 "이번 주"(2026-11-08 사용자 결정, 시안대로)** = 최근 정산 요약 + "API 키 등록" 카드.
- **내 정보 화면**: API 키 등록·교체·삭제. 시안에 없어 코드에서 A안 스타일로 바로 만든다(2026-11-08 사용자 결정).

### 3-1. 스케줄러 정보 조회 `GET /maplestory/v1/scheduler/character-state`

  `daily_contents[]`·`weekly_contents[]` = `{content_name, type('contents'|'quest'), registration_flag(인게임 스케줄러 등록 "true"/"false"), now_count, max_count, quest_state("0"기타·"1"진행 중·"2"완료)}`,

  `weekly_boss_clear_count`, `weekly_boss_clear_limit_count`.
- 결론: **완료 여부가 API 에 있다** → 직접 체크 없이 자동. "주별 놓친 횟수"는 14일 한도라 우리 DB 에 날마다 저장해 쌓아야 한다
